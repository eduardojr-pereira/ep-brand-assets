# Cards & Interactive Components

Load the shared styles and scripts in the order declared in `config/ui.json`. Use the canonical Jinja macros with HTML autoescaping enabled. No separate page builder is defined here.

## Contracts

- `badges(items)` accepts a list of `{src, label}` resolved by the consumer from the approved badge catalogue; no generated SVG copies. It renders nothing when empty.
- `project_card(project, labels)` accepts `title`, `description`, `collection` (`selected` or `learning`), `collection_label`, `areas` (space-free stable keys), `topics`, `badges`, optional `search` keywords, and `links` (`label`, `href`, `primary`). Supply only approved destinations and data. A primary link calls the diagonal macro from Navigation; other links use its underline primitive. No card-specific text/arrow animations.
- `catalog(id, projects, areas, labels)` wraps the cards in the approved 3/2/1-column grid (1050px and 650px breakpoints). `areas` contains `{value,label}`. Collection and area selectors are the canonical Navigation filters. Search matches visible text, supplied keywords and badge labels, without case/accent sensitivity; all query words and both filters must match. Clear, count and empty state are supplied; no projects are created or published by this component. The consumer passes localized labels (see test fixture for keys). When the future global language controller updates card contents/keywords, filter labels and count suffixes, it must emit `ui:languagechange` after DOM updates; this lot then refreshes filtering without resetting selections.
- `selected_projects(projects, labels)` accepts `title`, `subtitle` (optional), `description`, `badges`, `href`, `frames` (possibly empty), and `metrics` (possibly empty, `{value,label}`). Supply only projects approved as selected; the test fixture includes two synthetic slides to exercise navigation. Native horizontal scrolling/snap, keyboard arrows/Home/End and mouse drag are supported. Previous/next use the canonical Buttons macro; one item disables both controls. The evidence carousel advances using `--ui-duration-evidence-cycle` (4500ms), has manual dots and pause, suspends while offscreen, hidden, hovered, focused, inactive or reduced-motion, and uses supplied `{src,alt,caption}` with optional `light` and `dark` images. The evidence controller responds to `ui:themechange`; it does not own the theme. Counts, metrics and figures are supplied by the consumer and are not generated from test data. The component does not impose a fixed viewport height; the page composition will reconcile viewport geometry with the approved study and actual sticky header. Entry animation reuses `ui-motion-enter`; contextual timing follows the reference, but the exact clipping/reveal and frame crossfade choreography remain to be verified in the integrated Selected Projects section.
- `marquee(label, heading, email, href, pause, play)` renders the two approved opposite lanes, one actual contact anchor and one pause button. Uses the shared diagonal SVG, monochrome action colors and outCirc transition; the lens has a decorative synchronized copy, with no interactive duplicates. The two lanes move at 66px/s and 65% of that pace (42px/s base below 640px); hover pauses both in place and rotates the arrows toward the contact destination. The cursor is hidden only with a fine pointer and a live lens; reduced motion renders a static invitation, and touch keeps the normal link. Offscreen, inactive tab and explicit pause suspend movement. Initial lens diameter 112px reflects the study's default, not a separately approved dimension. Change `--ui-lens-size` (radius) contextually if necessary. On language change, update the original first unit text in each lane and accessible labels before emitting `ui:languagechange`; the controller reflows decorative copies. Use the email from brand configuration, not the fixture address. There are no experimental mask alternatives or study controls.

No new preview files, real project assets, test media or fonts are included in this lot. Contact Form fields, transport, About's asset integration, shared Lottie player, Header/Footer and global theme/language ownership remain later work. Report-specific tabs, reference slider and artifact explorer remain in their original migration scope, not extra requirements for the Landing Page.

## Verification

Run `python3 tests/test_interactive.py` with Jinja2, Playwright and Chromium (override browser path via `UI_TEST_BROWSER`). Tests compose the actual shared macros and CSS/JS from the first four lots; synthetic figures isolate behavior; canonical font loading is verified by the shared test fixture when the font files are available. The suite checks both themes, combined filters and reset, primary link text/arrow displacement, previous/next and manual evidence, monochrome lens synchronization, pause/resume, mobile/reduced-motion and static fallback. It does not certify actual project data, responsive page composition, Lottie playback, full translation or Pages publication.
