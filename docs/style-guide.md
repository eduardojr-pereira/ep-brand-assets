# Style Guide

The Style Guide is a consumer of the canonical builder and shared components, not a second component library. It uses the existing theme, localization, motion and asset services. The guide-only layout stylesheet arranges demonstration samples and displays semantic color tokens; it never defines shared component styles or theme values.

The explicit `style_guide` page kind is reserved for `style-guide/index.html`; it uses the same page plan, route validation, canonical shell and resource copying as other pages. The page uses the ten declared guide sections and their bilingual example text. Its layout resource is selected only when this page is declared. Ordinary builds omit the guide-only specimens, layout, script and optional Plotly.js runtime. They inherit the approved shared changes: bilingual institutional tagline, official logo, native external-link policy, return-link underlines and document-top anchor, footer-aware scroll selection, compact navigation and nested menus, indexed disclosures and Search-to-X artwork, animated icon presentation, report reference layout and the Plotly adapter. The 9C ordinary-build regression verified five fixture pages and 74 canonical resources (80 files total), with changes limited to the audited shared scope. The guide is a single editorial page; its cover, chapter index, specimens and layout reuse the existing visual foundations. No new runtime services are introduced.

The initial guide demonstrates foundations, editorial headings, links and actions, analytical primitives, motion and native disclosure. The link examples use matching guide fragments or corresponding sections of the local landing fixture. Standalone carousel arrows are omitted until the canonical working carousel is composed in the guide. Numbers and text are illustrative. The guide also composes the canonical catalogue, two-slide carousel, evidence controls, marquee and all 57 badge specimens from the active catalog. It copies those SVG files only for an explicitly declared guide, never for ordinary builds. Both language versions of status badges are shown as specimens, not validation outcomes. Artwork rights remain pending. The guide adds real Plotly line and heatmap specimens, the canonical palette preview, synthetic CSV/JSON artifact previews and a local send-state demonstration with no transport. The guide selects the shared optional Plotly.js runtime (4.1.1), sourced from pinned Plotly.py 7.1.0; the tagged upstream MIT license and source digest are recorded in THIRD-PARTY-NOTICES.md. The guide-only adapter calls the existing send-state API and owns no shared behavior. Technical landing/legal fixture routes are for local review only; no actual contact transport or production legal pages are implied.

The guide received visual approval and passed the isolated 9C technical regression (16 component suites, 49 build-only unit tests, eight Hangman tests and 14 integrated checks). The validated candidate may be installed on the checkpoint; no production deployment or third-party rights clearance follows from these approvals. Real consumer migration and publication checks remain pending.

Canonical web anchors use a non-sticky document-top target. Absolute HTTPS destinations open in a separate tab with noopener and noreferrer; relative routes, fragments, mailto and local downloads preserve native behavior. This policy is rendered by the shared navigation macro, not a runtime listener. The canonical header uses the same official shell image as the footer, with a localized accessible link label.

Both return links use the shared directional underline, hidden at rest and animated on hover or keyboard focus, in the same semantic accent as the incoming label. Only the label replacement axis differs. Reduced-motion settings remain respected.

Scroll navigation retains the last section until the canonical footer occupies strictly more than half of the viewport below the sticky header. The existing scroll controller clears section selection while the footer dominates and restores it on reverse scroll; a short footer does not clear selection merely because the document reaches its end.

The guide presents both native independent and exclusive indexed disclosures. The shared Search-to-X controller owns playback; native details grouping owns exclusivity. Modern browsers animate intrinsic panel height, while unsupported engines retain native behavior. Reference group labels sit outside their surfaces. Synthetic evidence SVGs and palette strips use the canonical catalog and do not represent real project findings. Guide-specific presentation context is isolated in tools/style_guide.py.

Badge specimens use a compact editorial grid with aligned locale groups. Only section links in the compact Header menu use the corner variant of the canonical arrow primitive; editorial links, radial actions and all other links keep their original diagonal artwork. Both variants share the existing motion. Nested disclosures use the native top layer for lateral placement when sufficient room exists, otherwise the same menu tree supports drilldown and return. Search-to-X fallback SVGs are removed from rendering whenever the player is ready.

Specimen observations originate in `style_guide/samples/observations.csv`: the line chart and displayed observation/series counts are derived from it. The summary JSON and evidence SVGs are generated specimen outputs; regenerate them when changing the CSV. The build rejects a stale summary. The heatmap and the analytical table are separate illustrative examples. The send fixture is outside a form and has no transport; its success state is a local, explicitly selected fixture acknowledgement, never a real server confirmation.
