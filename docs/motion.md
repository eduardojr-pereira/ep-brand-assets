# Motion Library

Load the shared styles and scripts in the order declared in `config/ui.json`. The motion controller is synchronous in the head; without JavaScript or IntersectionObserver, content remains visible. No separate page builder is defined here.

Apply `data-motion="fade|reveal-up|reveal-left|reveal-right|scale-in"` to a dedicated wrapper and `data-scroll-trigger="load|once|repeat"`. Left/right name the origin. `load` runs at DOMContentLoaded; `once` on viewport entry; `repeat` rearms after leaving the viewport. Do not nest motion wrappers unnecessarily or apply motion to an element whose transform is controlled by an interactive component. Use custom properties `--ui-motion-distance`, `--ui-motion-duration`, `--ui-motion-delay`, `--ui-motion-ease`, `--ui-motion-opacity`, `--ui-motion-scale` for contextual parameters. Stagger is composed through the delay property, not a second animation system.

Hero reference: the three lines enter left/right/left, from 100vw, opacity .15, duration 1650ms, delays 50/190/330ms; details fade for 1350ms after 700ms. These are contextual parameters in the future Hero component; do not apply them globally. Explicit replay is `UI.motion.replay(hero)` after the language controller changes the content; locale fade sequencing belongs to the language/Hero integration. No implicit replay on scroll for the Hero.

Global smooth scroll is an opt-in motion primitive via `data-ui-smooth-scroll`. Shared timings: 450ms diagonal link motion, 550ms directional underline, 550ms radial fill, 420ms navigation weight/color transition, 250ms feedback, 20s rotating label and 3370ms arrow cycle; orbital trail delays are derived from that cycle. Slide timings and marquee speeds are declared in the same motion tokens, preserving the approved values. Link effects, buttons, orbit behavior and marquee motion (including its contextual cursor lens) are implemented by their canonical components, not duplicated here. The real Landing Page Hero and final contextual integration remain pending. Continuous motion components must independently honor reduced motion and pause rules.

Default reveal duration 650ms, distance 24px, scale .96 and viewport threshold 0 are initial implementation values, subject to integrated visual verification. Reduced motion immediately reveals content. Returning to normal motion preserves all already visible content and restores explicit replay and repeat after a genuine viewport enter/exit. Keyboard focus reveals its containing motion wrappers. `ui-motion-fade-out` is available for explicit component transitions, never used to conceal ordinary page content automatically.

Run `python3 tests/test_motion.py` in an environment with Python Playwright and an installed Chromium-compatible browser. The test uses an isolated document, not a visual reference; browser executable selection can be overridden via `UI_TEST_BROWSER`. Final appearance, timing, layout and remote delivery must still be checked in the integrated page.

The optional `components/web/motion.html` declaration enables `data-motion-profile="editorial"` on an existing wrapper. The profile uses the same observer and keyframe: 1150ms, 30–52px travel and 130ms stagger steps (orders 0–4). This is opt-in, not a new global default. Existing interactive transforms remain on their own elements. Use repeat on editorial groups, once on the contact fields; preserve reduced-motion and keyboard-focus fallback.

Use `entry='in-view'` in the motion declaration for a delayed viewport entry (25% intersection), without changing the default edge-entry timing. `UI.motion.replay(scope, {visibleEditorial: true, top: headerHeight})` explicitly replays reached and visible editorial repeat targets after a caller updates content. It excludes once/load targets, offscreen elements and focused/targeted elements; it neither changes scroll position nor manages locale preference.
